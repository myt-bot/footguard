# FootGuard protocol v1.4 修订说明

## 修订范围

- 文档修订号升级为 1.4，`protocol_version` 仍为 1。
- `sensor_layout_version` 仍为 `layout_6p4t_v1`，BLE `layout_id` 仍为 2，SensorData 仍为 60 字节。
- 未改变字段、数组长度、帧偏移、BLE UUID、CRC、指令或 ACK 格式，无需因本次修订重刷固件。
- 明确 `quality_flags` 的通道级语义：温度点无效只排除对应温度证据，不影响压力显示、压力风险或压力马达；压力点无效不得被解释成正常零压力。
- HTTP 实时响应增加压力/温度总体可用状态和逐通道有效位；温差允许用 `null` 表达该同区对不可比较。
- 新增持久化的本次穿戴基线状态与重新标定流程；左右设备或布局不一致时旧基线失效。
- 新增结构化 AI 自由问答接口。大模型只接收当前状态摘要，不接收连续原始帧，也不参与风险等级或马达决策。

## 兼容性

已有 v1 固件能够提供所需的逐通道无效位，因此 App 和后端升级后原则上无需重刷 ESP32。只有实机确认固件未正确设置无效位、压力通道无法区分卡死/饱和，或左右固件 ACK 行为不一致时，才进入固件修复和重刷流程。
